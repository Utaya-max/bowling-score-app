# ボウリングスコア自動入力アプリ 要件定義・仕様書

## 1. システム概要
ボウリング場に設置されたスコアモニターの写真をユーザーがアップロードし、Gemini APIのマルチモーダル機能を用いて画像からスコアデータを抽出。構造化データとして画面上のテーブルに表示し、最終的にデータベースへ保存するWebアプリケーション。
※本システムはユーザー自身のスコア記録・管理を目的とする（複数人同時記録は初期要件スコープ外）。

## 2. システム構成（技術スタック）
* フロントエンド: Streamlit (Python)
  - 選定理由: HTML/CSSを記述せず、Pythonのみで機能的かつ無駄のないミニマルなUIを迅速に構築できるため。
* バックエンド: Python 3.x
* AI API: Gemini API (google-genai SDKを使用)
  - 使用モデル: gemini-2.5-flash （画像処理が高速かつ安価なため）
* データベース: SQLite
  - 選定理由: サーバー構築が不要で、手軽にRDBMSの基本操作を実装できるため。

## 3. 機能要件（実装する機能）

### 3.1. 画像アップロード機能
* デバイス内の画像ファイル（JPEG, PNG）を選択し、アップロードできること。
* スマートフォンからのアクセス時は、カメラを起動して直接撮影・アップロードできること。

### 3.2. AI解析機能
* アップロードされた画像をGemini APIへ送信し、以下の項目をJSON形式で抽出すること。
  - 店舗名（取得可能な場合）
  - 日時
  - レーン番号
  - プレイヤー名
  - 1〜10フレームの各投球スコア（ストライク・スペア等の記号含む）
  - 累計スコア（最終得点）

### 3.3. データ確認・編集機能（UI）
* AIが解析したデータを、画面上にデータテーブル（表）として表示すること。
* 【重要】 AIの誤認識に備え、ユーザーがテーブル上の数値を直接タップして手動修正できる機能を持たせること。

### 3.4. データ保存機能
* 確認・修正が完了したデータを、ボタン一つでSQLiteデータベースに保存（INSERT）できること。
* 過去の自身のスコア履歴を一覧表示（SELECT）できること。

## 4. データモデル設計（データベース構造）
対象をユーザー本人のスコアのみとするため、単一テーブルのシンプルな構造とする。

テーブル名: bowling_scores

| カラム名       | データ型     | 説明 |
| :------------- | :----------- | :--- |
| id             | INTEGER (PK) | 一意のID（自動採番） |
| play_date      | TEXT         | プレイ日時 (例: 2026-08-09 16:32) |
| location       | TEXT         | ボウリング場名 |
| lane_number    | INTEGER      | レーン番号 |
| player_name    | TEXT         | プレイヤー名 |
| frame_1        | TEXT         | 1フレームのスコア（カンマ区切り等） |
| frame_2        | TEXT         | 2フレームのスコア |
| frame_3        | TEXT         | 3フレームのスコア |
| frame_4        | TEXT         | 4フレームのスコア |
| frame_5        | TEXT         | 5フレームのスコア |
| frame_6        | TEXT         | 6フレームのスコア |
| frame_7        | TEXT         | 7フレームのスコア |
| frame_8        | TEXT         | 8フレームのスコア |
| frame_9        | TEXT         | 9フレームのスコア |
| frame_10       | TEXT         | 10フレームのスコア |
| total_score    | INTEGER      | 最終的な合計点数 |
| created_at     | DATETIME     | データ登録日時 |

## 5. 非機能要件
* UIデザイン: 装飾を極力排し、データの視認性と「撮影→確認→保存」の動線（機能性）を最優先したミニマルなデザインとする。
* レスポンス: Gemini APIの応答待機中は、ローディングスピナー等を表示し、ユーザーに処理中であることを明示する。
